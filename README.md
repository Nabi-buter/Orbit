# Orbit Duel

로블록스 "Dueling Grounds"를 모티브로 한 2D 픽셀 1:1 무기 대결. 훈련장(Range)에서 훈련봇끼리 싸운다.

2D 횡스크롤 1대1 무기 격투 게임 (브라우저, 외부 의존성 없음).

## 실행

```bash
npm start                          # 게임 서버: http://localhost:8080 (온라인 대전 WebSocket 포함)
npm test                           # 전투 규칙 자동 테스트 (Node 18+)
node scripts/e2e.cjs               # 브라우저 종단 테스트 (Playwright 필요)
node scripts/simulate.js 40 hard   # AI 대 AI 무기 상성 시뮬레이션
node scripts/balance-check.js      # 단순 전략 봇 / 거리별 판정 점검
node scripts/matrix.js 12          # 무기 상성표 (난이도 교차 AI 대전)
node scripts/tune.js 9 16          # 무기 밸런스 변수 자동 탐색
```

## 조작

| 동작 | P1 | P2 |
| --- | --- | --- |
| 이동 | A / D | ← / → |
| 점프 | W | ↑ |
| 가드 · 패링 | S | ↓ |
| 약공격 | J | Num1 또는 `,` |
| 강공격 (가드 브레이크된 상대 → 특수강공) | K | Num2 또는 `.` |
| 대시 (+방향, 또는 방향키 두 번) | Shift (왼쪽) | 오른쪽 Shift · Num3 · `/` |
| 궁극기 (게이지 100%) | I | Num5 또는 `;` |

**경기 규칙**: 목숨 2개. 한 명이 쓰러지면 둘 다 처음 위치에서 다시 시작하고, 쓰러진 쪽만 체력이 차고 버틴 쪽은 깎인 체력 그대로 시작한다(궁극기 게이지는 유지). 목숨이 먼저 다 떨어지는 쪽이 패배, 시간 종료 시 남은 목숨 → 체력 비율 순으로 판정.

Esc/P 일시정지 · F2 판정 박스 · M 소리 켜기/끄기. 키 배치는 `src/config/controls.js` 에서 바꿀 수 있다.

## 화면 / 그래픽

- 전체 화면을 427×240 도트 캔버스에 그린 뒤 정수 배율로 확대한다 (캐릭터·무기·모션·이펙트·HUD·메뉴 모두 픽셀).
- 타이틀 → **플레이** → 로드아웃 화면: 가운데 캐릭터(커스터마이즈 자리, 기능 미구현), 하단 1열 무기 7종, 상단 모드 탭(AI 대전 / 로컬 2인 / 온라인).
- 키보드(방향키·WASD·Enter·Esc)와 마우스 모두로 조작.

## 모션 / 그림 교체하기

- **공격 모션**: `src/render/motions.js` — 무기별 기본 자세(`STANCE`)와 콤보 단계별 키프레임(`MOTIONS`).
  판정·수치와 분리되어 있어 그림만 바꿔도 게임 규칙은 그대로다.
- **모션 뷰어**: `npm start` 후 `http://localhost:8080/tools/motions.html` — 모든 무기·단계를 재생/프레임 순서로 보여 준다 (판정 프레임 강조).
- **무기 그림**: `src/render/weaponArt.js` (절차 생성 스프라이트, 문자열 그림 `spriteFrom()` 으로 교체 가능)
- **캐릭터 그림**: `src/render/fighterArt.js` 의 `drawFighter()` — 마네킹형(큰 달걀형 머리·눈 띠·어두운 어깨/관절). 팀 색은 `renderer.js` 의 `TEAM`
- **캐릭터 확대 보기**: `http://localhost:8080/tools/sprite-zoom.html` (여러 자세를 8배로)

## 모드 / 무기

- **온라인 PvP**: 서로 다른 컴퓨터에서 방 코드로 대전 · **PvE**: AI 상대 (쉬움/보통/어려움) · **로컬 2인**: 한 키보드
  - AI 어려움: 완벽패링 실력은 그대로이고, 콤보를 상한까지 계획해 잇고(약공으로 길게 → 강공 마무리), 공격·가드 습관에 더해 움직임 습관(대시 돌진 · 점프 공격 · 치고 빠지기)도 찾아 공략한다.
    상대 다음 행동 예측은 실제로 맞아 온 비율만큼만 믿는다. 측정은 `node scripts/ai-strength.js` (어려움 vs 보통 · 분당 완벽패링 · 콤보 길이 · 습관 봇).
- 무기별 콤보 상한: 약공/강공 최대 연속 횟수(대검 약공 2, 단검 3, 너클 5 …)를 넘기면 "숨 고르기" 딜레이.
  약·강을 섞으면 더 길게 잇고 딜레이가 짧다. 콤보 직후 잠깐 빠졌다 다시 쳐도 같은 콤보로 계산된다.

## 설정

타이틀 → **설정**: P1 · P2 키 배치를 바꿀 수 있다(칸을 누르고 새 키 입력, 이미 쓰는 키면 서로 바뀜, ESC 취소).
터치 화면 버튼 켜기/끄기, **기본값으로 되돌리기**. 설정은 이 기기(브라우저)에 저장된다. ESC · Enter · Tab · M · P · F2 는 메뉴용이라 지정할 수 없다.

## 모바일

휴대폰·태블릿으로 열면 대전 중에 조작 버튼이 나온다(`src/ui/touch.js`). 가로·세로 모두 된다:
가로는 게임 화면 위에 버튼, 세로는 게임 화면이 위쪽에 꽉 차고 버튼이 그 아래에 크게(방향 패드 아래칸이 가드).
왼쪽 방향 패드(◀ ▶ 이동, 위로 밀면 점프, 손가락 미끄러뜨리기 가능) · 오른쪽 약공 / 강공 / 가드 / 대시 / 궁(게이지가 차면 빛남) · 위 Ⅱ 일시정지.
대전 중 위쪽 **버튼 끄기 / 켜기** 로 화면 버튼을 숨길 수 있다(키보드를 연결해 할 때, 기기에 기억됨).
메뉴는 탭으로 고른다. 온라인 방 코드는 '코드로 참가'를 누르면 입력창이 뜬다.

`claude/tender-wright-x9w8dw` 브랜치에 푸시하면 `.github/workflows/pages.yml` 이 테스트를 돌리고 통과하면
**https://nabi-buter.github.io/Orbit/** 에 배포한다. AI 대전 · 로컬 2인 · **온라인 대전** 모두 된다.
Pages 주소의 온라인 대전은 브라우저끼리 직접 연결(WebRTC, `src/net/peerLobby.js`)한다:
PeerJS 공개 중개 서버(0.peerjs.com)가 방 코드로 두 브라우저를 소개만 하고, 경기 데이터는 직접 오간다
(직접 연결이 막힌 망에서는 PeerJS 기본 TURN 서버로 중계). 확인: `node scripts/e2e-pages.cjs`.

## 온라인 대전

**시간 제한**: 방장(1P)이 방 화면에서 ◀ ▶ 또는 Q / E 로 60초 · **90초(기본)** · 120초 · **무제한** 중에 고른다 (AI 대전·로컬 2인은 99초).
손님에게 바로 보이고, 바꾸면 양쪽 준비가 풀린다. 무제한이면 목숨이 다 떨어질 때까지 싸운다(화면 위 시간 자리에 ∞).

**입력 전달**: 상대가 "여기까지 받았다"고 확인할 때까지 받지 못한 입력을 계속 다시 보낸다(빠지는 프레임 없음).
탭이 가려지면(다른 탭·앱 전환) 브라우저가 화면 루프를 멈추므로, 상대 입력이 올 때마다 따라 진행해 상대 화면이 멈추지 않게 한다.

**공유 링크(claude.ai)에서 — 서버 없이**: 두 사람 모두 claude.ai 에 로그인한 채 같은 링크를 열고 **온라인 대전**.
상대에게는 페이지 공유에서 **참여자(Contributor) 이상** 권한을 줘야 한다(보기 전용은 온라인 불가).
페이지의 실시간 방 기능이 서버 역할을 대신한다(`src/net/roomNet.js`): 방을 만든 쪽이 로비를 관리하고,
입력은 3프레임마다 최근 24프레임을 함께 실어 보내 메시지가 빠져도 다음 메시지가 메운다.

**직접 서버를 띄워서**:
1. 두 사람이 모두 접속할 수 있는 컴퓨터에서 `npm start` 로 서버를 실행한다
   (같은 공유기 안이면 서버 컴퓨터의 내부 IP `http://192.168.x.x:8080`, 인터넷이면 공인 서버나 포트포워딩).
2. 양쪽이 브라우저로 그 주소에 접속 → **온라인 대전**.
3. 한 명이 **방 만들기** → 4자리 코드를 상대에게 알려 주고, 상대는 코드를 입력해 **참가**.
4. 각자 무기를 고르고 **준비** → 대전 시작. 끝나면 로비에서 무기를 바꿔 재대결.

넷코드: 결정론적 시뮬레이션 + **락스텝(입력 지연)** 방식. 서버는 판정하지 않고 입력만 중계한다.
입력 지연은 두 플레이어의 핑을 보고 2~8프레임 사이로 자동 결정되고, 1초마다 상태 해시를 비교해 동기화 오류를 감지한다.
온라인에서는 P1/P2 어느 키 배치로도 내 캐릭터를 조작할 수 있다. 대전 중 일시정지는 없다(Esc: 메뉴/기권).
- 무기 7종: 장검 · 레이피어 · 대검 · 단검 · 도끼 · 창 · 너클
  - 레이피어: 한손 펜싱. 가늘고 긴 칼날로 멀리 빠르게 찌르지만(약공 사거리 2위) 판정이 얇고 한 타가 약하며 가드를 잘 못 깎는다. 강공 플레시(달려들며 찌르기), 궁극기 섬광 연격(높이를 바꿔 5연속 찌르기 → 런지)
- 무기별 밸런스 변수는 `src/config/weapons.js` 의 `KNOBS` 한곳: 콤보 · 리치 · 데미지 · 공격속도 (+ 보조: 체력 · 가드 감소량). 근거는 `docs/BALANCE.md`

## 구조

| 경로 | 역할 |
| --- | --- |
| `src/config/balance.js` | **모든 공통 밸런스 수치** (`[TEMP]` = 임시값) |
| `src/config/weapons.js` | 무기별 공격 데이터 (프레임/판정/피해/보정) |
| `src/config/controls.js` | 키 배치 |
| `src/core/fighter.js` | 플레이어 상태 데이터 |
| `src/core/actions.js` | 입력 → 행동 전환 |
| `src/core/physics.js` | 이동·중력·충돌·타이머·게이지 회복 |
| `src/core/combat.js` | 공격 판정, 피격/패링/완벽패링/가드 브레이크/특수강공 |
| `src/core/match.js` | 1프레임 시뮬레이션 (`step(inputs)`), 승패 |
| `src/core/ultimates.js` | 궁극기 타입 등록 구조 (무기별 궁극기 확장용) |
| `src/core/combo.js` | 무기별 콤보 상한 / 숨 고르기 딜레이 |
| `src/ai/ai.js` | PvE AI (지연 인지·난이도 수치) |
| `src/net/lockstep.js` | 온라인 락스텝 넷코드 (입력 지연, 해시 검사) |
| `src/net/client.js` | 온라인 서버 접속 클라이언트 |
| `src/net/roomNet.js` | 서버 없는 온라인 중계 로직 (방장이 로비 관리, 서버와 같은 프로토콜) — claude.ai 방 기능 / WebRTC 공용 |
| `src/net/peerLobby.js` | 일반 웹 주소(GitHub Pages)용 WebRTC 연결 (PeerJS 를 방 모양으로 감쌈) |
| `server/` | 게임 서버: 정적 파일 + WebSocket 방/입력 중계 (의존성 없음) |
| `src/input/` | 키보드 → 프레임 입력 |
| `src/game/app.js` | 화면 전환, 게임 루프, 히트스톱, 시작 연출 |
| `src/render/` | 도트 렌더링(`pixel.js` 기본 도구, 캐릭터·무기 스프라이트, 이펙트, HUD)·효과음 |
| `src/ui/screens.js` | 도트 UI 화면 (타이틀, 로드아웃, 조작법, 일시정지/결과, 온라인 로비) |
| `docs/BALANCE.md` | 밸런스 점검 기록과 수치 변경 이유 |

전투 로직(`src/core`)은 DOM·입력 장치·네트워크를 전혀 모른다. 양쪽 플레이어의 프레임 입력만 받아
결정론적으로 진행되므로(테스트로 검증), 온라인 대전은 입력 동기화(롤백/딜레이) 계층만 추가하면 된다.
